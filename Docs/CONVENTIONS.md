## 기술 선택 기준

구현 방식을 고를 때 아래 다섯 축으로 판정하고, 판정 근거를 함께 남긴다.

1. 실무성 — 실제 production에서 쓰이는 방식인가 (토이/데모 한정 방식 배제)
2. 범용성 — 이 프로젝트 특수해가 아니라 다른 프로젝트로 옮겨가는 방식인가
3. 공식 권장 — Epic 공식 문서·Lyra 등 1차 레퍼런스가 지시하는 경로인가(**5.7 스냅숏 우선, 없으면 5.8**. 프로젝트 엔진이 5.7.4다)
4. 최신성 — 현행 엔진 버전(5.7) 기준인가 (폐기·구버전 관행 배제)
5. 포폴 적합성 — 면접에서 설계 근거를 방어할 수 있는가

빠른 우회 방안은 대등한 선택지로 제시하지 않는다. 정식 방안을 확정 추천하고,
우회 방안은 명시적으로 요청받을 때만 언급한다

## 학습 구성

단원은 **학습 → 심화학습 → 실습 → 검증** 네 단계로 구성한다.(phase > stage > part 단위까지만 적용 그 이하의 세부항목까지 학습단계를 적용하기엔 일정이 늘어짐)

| 단계 | 하는 일 |
|---|---|
| 학습 | 개념과 계약. 이 단원이 무엇을 다루는지 한 문장으로 열고 시작한다 |
| 심화학습 | 공식 문서가 답하지 않는 것 — 선택지 전체, 실무 판단 기준, 버린 대안과 사유 |
| 실습 | 프로젝트 코드·애셋에 실제로 적용 |
| 검증 | 빌드·PIE로 기대 동작 확인 |

**심화학습은 선택 사항이 아니다.** 학습이 「무엇을 쓰는가」라면 심화학습은 「무엇을
쓰지 않기로 했고 왜인가」다. 참조 구현이 없는 영역일수록 이 단계가 설계 근거를 만든다.
이 단계가 빠지면 남는 것은 절차 안내뿐이고, 면접에서 방어할 것이 없다.

### 자료는 단원을 열기 전에 확보한다

단원이 건드릴 API 표면 **전체**를 미리 펼쳐 둔다. 쓸 것 하나가 아니라 선택지 전부를,
그리고 안 쓰기로 한 것은 사유와 함께.

출처 우선순위:
1. 공식 문서 — **5.7 스냅숏 우선, 없으면 5.8**
2. repo clone — 프로젝트의 현재 상태
3. Epic이 링크하는 커뮤니티 레퍼런스 — 버전 차이를 명시하고 인용

확보한 사실은 `ENGINE_NOTES_GAS.md`에 옮겨 적는다. **그 단원에 당장 필요한 것만
골라 적지 않는다** — 훑을 때 본 목록·선택지·프로퍼티 전체를 남긴다. 골라 적으면
다음 단원에서 같은 조사를 다시 하게 된다.

**단원이 열린 뒤에는 조사하지 않는다.** 진행 중 조회가 필요해지면 자료 확보가
부실했다는 신호이므로, 단원을 물리고 확보 단계로 돌아간다.

## 로깅
- `LogTemp` 사용 금지 (신규 코드 포함)
- 카테고리 4종: `LogSaytCombat`(전투·GAS·캐릭터) / `LogSaytData`(데이터·저장·인벤토리) /
  `LogSaytUI`(Slate·HUD) / `LogSaytEditor`(에디터 모듈)
  — 선언 위치: `SaytLogChannels.h/.cpp`, 에디터 모듈은 `SaytEditor.h/.cpp`
- 레벨 의미론:
  - `Error`: 깨진 불변식·설정 누락 — 프로그래머가 고쳐야 함
  - `Warning`: 복구했지만 의심스러운 상태 — 조사 가치 있음
  - `Log`: 저빈도 라이프사이클 이벤트 — 세션 로그에서 흐름이 읽히는 정도
  - `Verbose`: 개발용 흐름 추적, 기본 꺼짐 — 콘솔 `log <카테고리> Verbose`로 점등
- 새 디버그 로그는 처음부터 `Verbose`로 작성한다 — 작업 후 삭제가 아니라 소등
